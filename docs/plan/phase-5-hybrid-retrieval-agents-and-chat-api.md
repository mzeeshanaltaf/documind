# Phase 5 — Hybrid Retrieval, Agents & Chat API

**Goal:** Build the backend that answers questions with citations:
- Retrieval is hybrid: true BM25 in SQL plus pgvector, fused with RRF.
- An orchestrator routes each question to department specialists.
- The answer is generated by one streamed synthesis call, sent as SSE.
- Every LLM call is metered.
- The phase also adds the conversations, feedback, settings and analytics APIs, and a retrieval eval that proves hybrid beats either method alone.

**Depends on:** Phase 4 (seeded `simtora` org). **Unblocks:** Phase 6.

## 1. BM25 in SQL — `api/app/rag/bm25.py`
- **Why SQL.** pg_search is not available, so this is genuine Okapi BM25 over `chunk_terms` (k1=1.2, b=0.75).
- **Query terms** come from `tokenizer.term_freqs(query)`. Query term frequency is ignored; each term counts once.

```sql
WITH q(term) AS (SELECT unnest(CAST(:terms AS text[]))),
s AS (SELECT n_chunks, avg_len FROM bm25_stats WHERE org_id = :org),
df AS (SELECT ct.term, count(*)::float AS df
       FROM chunk_terms ct JOIN q USING (term)
       WHERE ct.org_id = :org GROUP BY ct.term)
SELECT ct.chunk_id,
       sum( ln(1 + (s.n_chunks - df.df + 0.5) / (df.df + 0.5))
            * (ct.tf * (:k1 + 1)) / (ct.tf + :k1 * (1 - :b + :b * c.bm25_len / s.avg_len)) ) AS score
FROM chunk_terms ct
JOIN q USING (term) JOIN df USING (term)
JOIN chunks c ON c.id = ct.chunk_id
CROSS JOIN s
WHERE ct.org_id = :org
  AND (CAST(:doc_ids AS uuid[]) IS NULL OR c.document_id = ANY(:doc_ids))
  AND (CAST(:depts AS text[]) IS NULL OR c.department = ANY(:depts))
GROUP BY ct.chunk_id
ORDER BY score DESC
LIMIT :k;
```

- **Test against `rank_bm25.BM25Okapi`** on a toy corpus. Insert it inside a transaction under a temporary org row and roll back afterwards, then assert that the ranking and scores match within 1e-6.
  - rank_bm25's idf variant differs slightly. Either use `BM25Plus`/custom idf in the reference, or compare against a small pure-Python implementation of the same formula.

## 2. Vector search — `api/app/rag/vector.py`
- **Session settings** for each search: `SET LOCAL hnsw.ef_search = 100; SET LOCAL hnsw.iterative_scan = relaxed_order;`. This is pgvector 0.8, so filtered queries still return k rows.
- **Re-sort the results,** because relaxed order can come back out of order:
  ```sql
  WITH r AS MATERIALIZED (
    SELECT id, embedding <=> :qvec AS dist FROM chunks
    WHERE org_id = :org AND <same optional doc/dept filters>
    ORDER BY embedding <=> :qvec LIMIT :k)
  SELECT id, 1 - dist AS sim FROM r ORDER BY dist;
  ```
- **Query embedding.** One `embed()` call for all of the router's queries (operation `embed_query`).

## 3. Fusion & selection — `api/app/rag/hybrid.py`
- **Run in parallel.** For each (query × specialist filter) pair, run BM25 top 30 and vector top 30 with `asyncio.gather`. **Each one needs its own session/connection**, because an AsyncSession is not concurrent.
- **Reciprocal Rank Fusion.** Across all lists, `rrf(chunk) = Σ 1/(60 + rank)`.
- **Jurisdiction boost,** when the router returns jurisdiction J:
  - ×1.25 if the chunk's jurisdiction is J;
  - ×1.0 if it's `GLOBAL`;
  - ×0.8 if it's a different country-specific jurisdiction.
  - With no J, prefer the base-document jurisdiction (×1.0) and leave the others unchanged.
- **Department fallback.** If a department-filtered list returns fewer than 3 hits, also run that query unfiltered.
- **De-duplicate.** Between two adjacent chunks (same doc, `chunk_index ±1`, overlapping text), keep the higher-scoring one.
- **Select.** Take the top `org_settings.top_k` (default 8) within a token budget of about 6,000.
  - If a chosen chunk is a table fragment, pull in its adjacent `chunk_index` fragment.
- **Return** `Source` objects, numbered 1..n in rank order:
  `{n, chunk_id, document_id, doc_code, title, section_path, section_number, page_start, page_end, content_type, text, scores{bm25_rank, vector_rank, rrf}}`.

## 4. Agents — `api/app/agents/`
- **`catalog.py`.** `get_org_catalog(org_id)` returns the departments and jurisdictions present, plus for each `ready` doc: code, title, dept, juris, doc_type, summary and applies_to.
  - Cache it in memory per org with a 5-minute TTL. Invalidate it on document create, update or delete.
- **`router.py`** (the orchestrator).
  - **Call.** `respond()` with `router_model` on the **chat tier**, using a strict json_schema.
    - **Prompt layout.** For prompt caching, put the static content first (system instructions, then the org catalog), then the last 6 turns of history, then the question.
  - **Output schema:**
    ```json
    { "departments": ["HR"],            // 1-3, from catalog departments; [] = general/unknown
      "jurisdiction": "DE" | null,       // only if stated or clearly implied
      "standalone_query": "…",           // resolved follow-up, self-contained
      "sub_queries": ["…"],              // 0-3 decompositions for multi-part questions
      "needs_clarification": false,
      "clarifying_question": null }
    ```
  - **Clarification policy.** Ask only when the answer materially differs by country, the user gave no hint, and the catalog has more than one jurisdiction for that topic. Even then, prefer answering with the base policy plus a note about country variations. When clarification is needed, stream the clarifying question as the assistant message and skip retrieval.
  - **Bypass.** If the request has `document_ids`, skip routing apart from query rewriting. Retrieval uses no department filter, only those docs.
- **`specialists.py`.**
  - **`SPECIALISTS: dict[str, Specialist]`.** `Specialist(department, persona, rules)` entries exist for HR, IT, Finance, Procurement, Facilities, Compliance, Corporate and International.
    - HR rule: *"Country manuals override the base HR manual for employees of that subsidiary — state which applies."*
    - Finance/Procurement rule: *"Quote exact approval thresholds and approvers."*
    - Compliance rule: *"Point to reporting channels."*
  - **Unknown departments** get a generic template.
  - **Multiple departments.** Merge the personas into the synthesizer instructions and retrieve per department.
- **`answer.py`** (the synthesizer). A streamed `responses.create(stream=True)` on the **chat tier** with `chat_model`.
  - **Instructions:**
    - Answer only from the numbered sources.
    - Cite every factual sentence with `[n]`, and combine citations as `[1][3]`.
    - If the sources don't contain the answer, say so plainly and suggest who owns the policy (from the doc owner field).
    - Call out jurisdiction differences.
    - Use concise Markdown with bullets and tables where helpful. Never invent numbers.
  - **Sources block.** Each source is formatted as `[n] {doc_code} · {title} · §{section_number} {section_title} · p.{page_start}{-page_end}\n{text}`.
  - **Usage and timing.** Capture TTFT at the first `response.output_text.delta`, and usage from `response.completed`. Record the usage with operation `answer`.
- **Citations.** `citations.py` finds the `\[(\d+)\]` markers, keeps only the cited sources (in first-cited order), and drops invalid numbers.
  - **Citation object:** `{n, document_id, doc_code, title, section_number, section_title, section_path, page_start, page_end, snippet (first ~280 chars), highlight_text (full chunk text for the PDF highlighter)}`.

## 5. Chat API — `api/app/routers/chat.py`
**`POST /v1/orgs/{org_id}/chat`**
- **Request body:** `{conversation_id?: uuid, message: str (1..4000), document_ids?: uuid[]}`.
- **Response:** `EventSourceResponse` (sse-starlette).
- **Flow:**
  1. Load or create the conversation; it must belong to the actor and org. A new conversation's scope is `docs` if `document_ids` is set.
  2. Insert the user message.
  3. Route, retrieve and synthesize.
  4. Insert the assistant message with content, citations, sources, routing and retrieval (ranks and scores per source).
  5. For a new conversation, generate a title asynchronously after `done`: a ≤ 6-word title, operation `title`, on the background tier.
- **SSE events,** in order (the `data` field is JSON):
  - `meta` → `{conversation_id, user_message_id, assistant_message_id}`
  - `routing` → `{departments, jurisdiction, standalone_query, bypassed: bool}`
  - `sources` → `[{n, doc_code, title, section_number, page_start}]`
  - `delta` → `{text}` (repeated)
  - `citations` → `[Citation]`
  - `usage` → `{input_tokens, cached_tokens, output_tokens, cost_usd, latency_ms, ttft_ms}`, totalled across router, embedding and answer
  - `done` → `{}`
  - `error` → `{message}`
- **Disconnect.** If the client disconnects (`await request.is_disconnected()`), cancel generation and save the message with `status='stopped'`.

## 6. Other APIs
- **Conversations** (`routers/conversations.py`):
  - `GET /v1/orgs/{org_id}/conversations?limit&cursor`: the actor's own conversations, newest first.
  - `GET /v1/conversations/{id}`: with messages.
  - `PATCH` rename.
  - `DELETE`.
  - **Ownership.** Only the owner may access a conversation. Admins can't read other users' chats unless that's added later; keep it owner-only for now.
- **Feedback.** `POST /v1/messages/{id}/feedback` takes `{value: 1|-1, comment?}`. Only the conversation owner can submit it.
- **Settings** (`routers/settings.py`, admin):
  - `GET/PUT /v1/orgs/{org_id}/settings`.
  - **Validation.** Models must be keys in the pricing file; tiers must be one of `standard|flex|auto`; `top_k` is 4..15.
  - **Defaults.** Missing values fall back to the env defaults; GET returns the effective values plus `pricing` for the UI.
- **Analytics** (`routers/analytics.py`, admin). `GET /v1/analytics?org_id=<optional>&from&to&granularity=day` returns:
  - `totals`: requests, input, cached and output tokens, cost, cache_hit_pct = cached / input, p50/p95 `latency_ms` and `ttft_ms` for `answer` via `percentile_cont`, and the message count.
  - `timeseries`: cost and tokens per day.
  - `by_operation`, `by_model_tier`.
  - `by_user` (top 10, joined to `"user"` for the email).
  - `by_agent`, via `messages.routing->'departments'` unnested.
  - `top_documents`: from `jsonb_array_elements(messages.citations)` grouped by `doc_code`.
  - `feedback`: up and down counts.
  - `GET /v1/admin/orgs` gives the admin overview: each org with document count, member count and 30-day cost.

## 7. Retrieval eval — `api/eval/`
- **`golden.jsonl`** has about 25 lines of the form `{question, expected_doc_codes: [...], expected_sections?: [...], jurisdiction?}`.
  - **Read the PDFs to write the questions and confirm the answers.**
  - Cover HR base, each country manual, IT, Finance, Procurement, Facilities, Compliance, and cross-department questions.
  - Include exact-code questions ("What does SIM-PRC-001 say about…"), which favour BM25, and paraphrased ones ("can I bring my dog to the office"), which favour vectors.
  - Starter set:
    - "What are the stages of the grievance procedure and timescales?" → SIM-HR-001 §3.1
    - "How long does a performance improvement plan last?" → SIM-HR-001 §2.4
    - "How much paid time off do employees in Germany get?" → SIM-HR-102
    - "Is there a home office or connectivity stipend?" → SIM-HR-001 §7.4
    - "Can I use AI tools like ChatGPT for work?" → SIM-HR-001 §1.9 and/or SIM-IT-001
    - "Who approves a purchase above the procurement threshold?" → SIM-PRC-001
    - "How do I report a compliance concern anonymously?" → SIM-HR-001 §3.3 and/or SIM-CMP-001
    - "What is the visitor policy for our offices?" → SIM-FAC-001
- **`run_eval.py`** (`uv run python -m eval.run_eval --org-slug simtora`). Retrieval only, with no answer generation. It reports hit@5, hit@8 and MRR for **bm25-only, vector-only and hybrid**, plus routing accuracy (expected department ∈ routed). Results are written to `api/eval/results/<date>.md`.
- **Target:** hybrid hit@8 ≥ max(bm25, vector) and ≥ 0.85. If it falls short, tune the boosts and chunking, and record the changes in Status.md.
